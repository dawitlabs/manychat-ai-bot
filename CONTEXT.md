# ManyChat AI Fitness Bot

An AI bot that impersonates "Kyle," a men's fitness coach, running leads through a scripted sales funnel on Instagram and Facebook DMs via ManyChat, with the goal of booking them onto a Calendly discovery call. Current focus: AI capability improvements and the `apps/web` operator dashboard. `apps/admin` is parked for later.

## Language

**Lead**:
A social media user the bot is actively messaging. Stored as a single record keyed by `user_id` — one Lead, one continuous conversation thread.
_Avoid_: contact, prospect, user

**Conversation**:
The full message thread between Kyle and a Lead. A Lead has exactly one Conversation — they are not separate entities.
_Avoid_: thread, chat, session

**Message**:
A single turn in a Conversation, with a role of `user` (the Lead) or `assistant` (Kyle).
_Avoid_: reply, text, chat message

**Funnel Step**:
An integer (1–6) indicating which step of the qualification funnel Kyle is currently executing with a Lead. Advanced automatically by an AI classification call after each reply.
_Avoid_: stage, phase, step

**Status**:
The commercial state of a Lead in the sales pipeline. Valid values: `New`, `Engaged`, `Qualified`, `Booked`, `Closed`, `Lost`.
_Avoid_: state, stage, label

**Source**:
How the Lead's Conversation was initiated. One of: `comment` (Lead commented on a post, bot sent an opening DM), `instagram_dm` (Lead DM'd directly on Instagram), `facebook_dm` (Lead DM'd directly on Facebook).
_Avoid_: channel, origin, platform

**Platform**:
The social network the Lead is on: `instagram` or `facebook`. Distinct from Source — a `comment`-sourced Lead still has a Platform of `instagram` or `facebook`.
_Avoid_: channel, network

**Funnel**:
The fixed 6-step qualification script Kyle follows: (1) Goal → (2) Nutrition → (3) Biggest Struggle → (4) Offer Help → (5) Pivot to Call → (6) Send Booking Link. Steps must not be skipped or reordered.
_Avoid_: script, flow, sequence

**Opening DM**:
The first message Kyle sends to a Lead who initiated via `comment` source. Generated by the `COMMENT_REPLY_PROMPT`, references the Lead's specific comment to feel personal.
_Avoid_: intro message, first message, cold DM

**Booking Link**:
The Calendly URL sent at Funnel Step 6. The call it books is free; the coaching program discussed on the call is paid. Stored as a separate DB setting (`booking_url`), not hardcoded inside the system prompt.
_Avoid_: call link, calendar link, Calendly link

**Bot Settings**:
Operator-configurable values stored individually in the `settings` table: `system_prompt`, `booking_url`, `coach_name`, `program_length`. Separating these from the prompt text allows white-labelling without editing raw prompt copy.
_Avoid_: config, environment variables, prompt variables

## Relationships

- A **Lead** has exactly one **Conversation**
- A **Conversation** contains one or more **Messages**
- Each **Message** has a role: `user` (Lead) or `assistant` (Kyle)
- A **Lead** has one **Source**, one **Platform**, one **Status**, and one **Funnel Step**
- A **Lead** with Source `comment` received an **Opening DM** before their Conversation began

## Example dialogue

> **Dev:** "When a Lead comments on a post, do we create the Conversation immediately?"
> **Domain expert:** "Yes — the /comment endpoint fires, generates an Opening DM, and that DM becomes the first Message in the Conversation. Source is set to `comment`."

> **Dev:** "If the same Lead DMs again six months later, do we create a new Conversation?"
> **Domain expert:** "No — same user_id, same Lead, same Conversation. History continues from where it left off (or has expired and resets)."

**History Window**:
The full message history for a Lead, persisted in Postgres. No time-based expiry — history persists until an admin explicitly resets it via `POST /reset`. Only the last 40 Messages are sent to OpenAI per call (rolling window); older messages stay in the DB but are not included in the AI context.
_Avoid_: session, window, expiry

## Flagged ambiguities

- "conversation" and "lead" were used interchangeably in the codebase — resolved: they are the same entity. Use **Lead** when discussing the person, **Conversation** when discussing the message thread. The DB table is `conversations` but represents Leads.
- `funnel_step` was not being updated by the AI — resolved: it should be advanced via a separate AI classification call after each reply (not yet implemented).
